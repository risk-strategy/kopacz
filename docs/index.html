Kopacz v3

A cryptographically authenticated, adaptive DNS transport protocol and multi-application Tor relay for bidirectional communication over constrained or censored networks.

Why Kopacz v3?

Traditional DNS tunnels suffer from two fatal flaws: per-fragment encryption overhead (which wastes up to 82% of each DNS query on nonces and MAC tags) and stop-and-wait polling stalls across recursive resolvers.

Kopacz v3 decouples cryptographic framing from DNS fragmentation: application messages are compressed with LZ4 and sealed once with ChaCha20-Poly1305 (a flat 28-byte overhead per message), then sliced into order-independent fragments carried over self-clocked DNS query pipelines.

5-Layer Protocol Architecture

+-----------------------------------------------------------------------------------+
| Layer 5: Multiplexed Applications (1-Byte App ID)                                 |
|   0x01 CONNECT Proxy   | 0x02 TCP/SSH Bridge | 0x03 E2E Dead-Drop | 0x04 WebFetch |
+-----------------------------------------------------------------------------------+
| Layer 4: Session State Machine, Selective Repeat ARQ & Conditional LZ4            |
|   64-Packet RecvWindow | Piggybacked ACK_LOW8 | Self-Clocked Poll Pipeline        |
+-----------------------------------------------------------------------------------+
| Layer 3: Cryptographic Engine                                                     |
|   1-RTT X25519 ECDH + PSK (UTC Timestamp + Transcript AAD)                        |
|   ChaCha20-Poly1305 AEAD (28B/msg) + 64-Packet Sliding Anti-Replay Bitmap         |
+-----------------------------------------------------------------------------------+
| Layer 2: Framing & Fragmentation                                                  |
|   8-Byte Big-Endian Header + 8-Byte AEAD Control MAC (on ACK / POLL / FIN)        |
+-----------------------------------------------------------------------------------+
| Layer 1: Adaptive DNS Carrier                                                     |
|   Upstream QNAME (Base32 / Base36) | Downstream TXT or Synthesized AAAA (2000::/3)|
+-----------------------------------------------------------------------------------+

8-Byte Wire Header + Control MAC

Every packet begins with a compact 8-byte big-endian header: Flags(1) ‖ StreamID(2) ‖ Sequence(2) ‖ FragIndex(1) ‖ TotalFrags(1) ‖ Reserved(1). Standalone control frames (ACK, POLL, FIN) append an 8-byte AEAD control MAC so spoofed UDP packets can never reset a session or drain downstream queues.

1-RTT Forward-Secret Handshake

Clients generate an ephemeral X25519 keypair and seal c_pub ‖ utc_timestamp(8B) under the 256-bit PSK with AAD "kopacz-v3-syn". The relay verifies timestamp freshness (±300s), rejects replayed SYN nonces, and replies with s_pub bound to "kopacz-v3-synack:" ‖ c_pub. Directional keys are derived via HKDF-SHA256.

Bimodal Threat Model & Transport Postures

A traveler bypassing a captive Wi-Fi portal and a human rights defender operating inside a censored network face fundamentally different adversaries. Kopacz v3 adapts its wire footprint via three transport postures:

Posture DNS QTYPE Max Label Up / Down MTU Concurrency Pacing Jitter Target Environment
turbo TXT 63 chars 120 B / 480 B 4× pipelined 0 ms Captive portals & high-throughput bulk transfer
balanced TXT 50 chars 100 B / 240 B 2× pipelined 5–25 ms Default general-purpose operation across public resolvers
covert AAAA 32 chars 56 B / 112 B 1× serial 150–600 ms High-DPI censored networks (encodes downstream in 2000::/3 IPv6 records)

Multi-Platform Clients

Python CLI & .pyz

Unified kopacz-client supporting socks, ssh, fetch, and chat. Package into a single executable kopacz.pyz with ./scripts/build_pyz.sh.

Zero-Dependency C99

clients/c/kopacz.c compiles with any C99 compiler into a ~35 KB static-friendly binary with embedded X25519, ChaCha20-Poly1305, HKDF-SHA256, LZ4, and raw UDP/53 DNS.

Bash & PowerShell

Drop-in wrapper scripts in clients/bash/kopacz.sh and clients/powershell/kopacz.ps1 for POSIX workstations and Windows PowerShell 5.1+/7+.

Single-File DoH Browser

Open kopacz/apps/clients/web.html directly from disk. Uses DNS-over-HTTPS with sticky provider failover and Relay Reader Mode DOM distillation.

Relay Reader Mode (0x04)

FETCH_READER distills bloated multi-megabyte webpages on the relay into a clean, self-contained HTML+CSS bundle delivered in a single compressed burst.

E2E Dead-Drop Chat (0x03)

End-to-end X25519 + ChaCha20-Poly1305 messaging where handles are cryptographically pinned to owner public keys on both the relay and client.

Client Quickstart Examples

export KOPACZ_DOMAIN="t.example.com"
export KOPACZ_PSK="$(python3 -c 'import secrets; print(secrets.token_hex(32))')"

# 1. Fetch a webpage using Relay Reader Mode (distilled HTML)
kopacz-client fetch https://www.bbc.co.uk --reader

# 2. Start a local SOCKS5 proxy on 127.0.0.1:1080 in TURBO posture
kopacz-client socks --bind 127.0.0.1:1080 --posture turbo

# 3. SSH over DNS via ProxyCommand
ssh -o ProxyCommand="kopacz-client ssh --tag bridge" user@target

# 4. Build and run the zero-dependency C99 client
cc -O2 -Wall -Wextra -std=c99 -o kopacz clients/c/kopacz.c
./kopacz -d "$KOPACZ_DOMAIN" -k "$KOPACZ_PSK" fetch https://example.com

Security Hardening & Verification

Defense-in-Depth Relay Isolation

All relay HTTP/TCP egress routes through Tor SOCKS5 with a kernel-level iptables -I OUTPUT 1 -m owner --uid-owner kopacz kill-switch, strict DNS resolution SSRF guards blocking RFC 1918/6598/loopback/link-local ranges on every redirect hop, and stripped non-HTTP URL handlers.

293 Automated Tests

Verified by 293 unit, Hypothesis property-based fuzzing, RFC conformance (tests/test_rfc_conformance.py), and security audit regression tests (tests/test_security_audit.py) covering control-plane MACs, fragment poisoning, window bounds, and handle ownership.
